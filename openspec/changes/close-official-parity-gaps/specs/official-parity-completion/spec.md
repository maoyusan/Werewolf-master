## MODIFIED Requirements

### Requirement: 官方来源是唯一判断标准

系统必须以固定版本的官方 `Roles.cs`、`Werewolf.cs`、`GameBalancing.cs`、`Settings.cs` 和 `IPlayer.cs` 为规则依据。Python 现有行为或旧测试不能单独作为“官方正确”的证明。

#### 场景：发现实现和官方不同

- **当** 对照发现规则、顺序、限制、死因、阵营或胜负结果不同
- **那么** 先修改实现，再增加能稳定复现该差异的测试
- **并且** 对照清单保持未完成，直到测试通过且来源位置已记录

### Requirement: 剩余官方分支全部有测试

系统必须覆盖并验证以下分支：`RandomLynch`、`SecretLynch` 及其展示开关、Augur 可能身份顺序、掘墓人按人数变化的公式、SerialKiller 相关配置和绊倒规则、全部转化概率边界、访问者死亡、化学家/盗贼/巫师/分身的二人和三人残局。

#### 场景：边界概率为 0% 或 100%

- **当** 某个官方概率被固定为 0% 或 100%
- **那么** 结果必须稳定地分别表现为“不发生”或“一定发生”
- **并且** 角色死亡、转化、访问结果和胜负结果必须与官方一致

#### 场景：同一规则在不同人数下运行

- **当** 规则涉及玩家人数、活人数量、狼人数量或恋人数量
- **那么** 测试必须至少覆盖规则的最小人数、临界人数和普通人数
- **并且** 不能用只适用于默认人数的固定结论代替官方公式

### Requirement: 100%完成标记有证据

只有在每条清单项目均有官方来源、可执行测试和通过结果时，清单才可以标记完成。任何“只覆盖默认值”“只测文本”“只靠人工确认”的项目都不能标记为代码级完成。

#### 场景：全量对照完成

- **当** 运行官方对照测试、JSON fixture 测试和命令测试
- **那么** 所有测试必须通过
- **并且** 清单中不得保留未闭环项目，或必须明确标注为平台行为而非玩法规则
