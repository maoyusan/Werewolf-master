## Purpose

在官方玩法分支已完整盘点后，把所有确认差异集中修复并重新验证，确保修复结果可追溯、可回退，且不会漏掉同一流程中的相邻差异。

## ADDED Requirements

### Requirement: 必须先冻结完整差异清单

系统在改动玩法代码前必须完成官方分支总表第一轮检查。只有所有玩法条目均为已通过、已差异或已确认未调用，且未检查和未决数量为零时，才可以冻结差异清单并开始修复。每个差异必须有唯一编号、官方来源、固定最小输入、当前 Python 结果和官方期望结果。

#### Scenario: 检查尚有空白

- **WHEN** 分支总表仍有未检查或未决条目
- **THEN** 系统不得将差异清单标记为完整，也不得给出一次性修复完成的结论

#### Scenario: 冻结差异清单

- **WHEN** 第一轮分支总表不存在未检查和未决玩法条目
- **THEN** 系统必须输出全部差异编号和数量，作为本轮集中修改的固定范围

### Requirement: 每个确认差异必须先有稳定最小测试

系统必须在修改前为每个差异新增或明确对应一项稳定测试。测试必须固定初始状态和输入，断言至少一个相关游戏结果，并能在未修复时失败、修复后通过。

#### Scenario: 夜晚行动差异

- **WHEN** 官方与 Python 在同一夜晚输入下得到不同的目标、死亡、保护、转换或事件结果
- **THEN** 测试必须固定该夜晚状态并断言差异字段，随后才允许修改实现

#### Scenario: 设置或恢复差异

- **WHEN** 差异只在特定人数、设置、快照或恢复后出现
- **THEN** 测试必须包含该设置或完整快照，不能以普通默认对局替代

### Requirement: 所有确认差异必须在同一轮修复中关闭

系统必须按共享规则、角色行为、阶段推进、保存恢复和 QQ 入口的依赖顺序集中修复冻结清单中的全部差异。每项修复后必须重新检查受影响的官方总表条目；新发现的差异必须重新打开总表并纳入同一轮，直到差异数归零。

#### Scenario: 一个修复影响相邻规则

- **WHEN** 修复后某个已通过条目变为不同结果，或出现新的官方差异
- **THEN** 系统必须将该条目登记为差异并继续本轮修复，不得留作后续未说明工作

#### Scenario: 冻结清单全部通过

- **WHEN** 所有冻结差异及修复期间新增差异均已通过其最小测试和复查
- **THEN** 差异数必须更新为零，并进入完整回归验证

### Requirement: 修复完成必须经过完整复查和可回退交付

系统必须运行官方分支总表的逐条复查、Python 反向检查、官方对照测试、QQ 指令测试、保存恢复测试和全量测试。每个修复组必须保存原始哈希、副本、修改后文件、差异文件、命令输出和可执行回滚脚本；回滚脚本必须在临时副本实际运行并验证。

#### Scenario: 完整验证通过

- **WHEN** 所有差异修复完成
- **THEN** 所有规定测试和双向分支检查必须通过，并记录命令、关键输出和退出状态

#### Scenario: 回滚验证

- **WHEN** 交付修复材料
- **THEN** 回滚脚本必须先在临时副本恢复修改前行为并通过对应验证，再记录为已验证
