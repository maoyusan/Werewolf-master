## Purpose

约定运维打开 `/dashboard` 时如何以企业级检测台阅读对局健康、连接态与投递异常，并保证页面只读、自包含且状态不只靠颜色传达。

## ADDED Requirements

### Requirement: 检测页按分区呈现健康与对局
系统必须在 `/dashboard` 提供一份完整的超文本检测页。宽屏必须采用左侧应用壳与右侧工作区的左右布局：左侧呈现品牌与分区导航，右侧呈现连接态、服务健康摘要、总览指标卡片、对局诊断卡、全局流程日志、异常投递。各分区必须有标题层级，不得把全部信息挤成无标题的单列表。

#### Scenario: 打开检测页能看到分区骨架
- **WHEN** 运维访问 `/dashboard`
- **THEN** 页面标题表明这是狼人杀运行检测台
- **AND** 页面同时包含左侧导航、连接态、总览指标、对局区、全局流程日志与异常投递这些可定位区域

#### Scenario: 有对局时先看到诊断再看到明细
- **WHEN** 快照中存在至少一个活跃对局
- **THEN** 每个对局卡片顶部展示诊断级别、诊断结论与说明
- **AND** 玩家表、投票、夜间行动、日志与投递明细出现在该诊断条之后，而不是盖过诊断结论

### Requirement: 状态同时用文字图标与颜色表达
系统必须用文字标签、语义色与矢量图标共同表达连接态、网关就绪、诊断级别（正常、提示、警告、错误）以及失败类指标。禁止只靠颜色或只靠圆点传达上述状态。图标必须是内联矢量图形，不得用表情符号充当结构图标。

#### Scenario: 诊断级别可读且不只靠颜色
- **WHEN** 某对局诊断级别为警告或错误
- **THEN** 该卡片同时显示级别中文名、对应矢量图标与语义色背景
- **AND** 即使忽略颜色，运维仍能从文字读出级别

#### Scenario: 网关离线不只靠变色
- **WHEN** 快照显示网关未就绪
- **THEN** 健康摘要用中文写明离线或未就绪，并配警告或错误图标
- **AND** 不得只把数字或圆点改成红色

### Requirement: 连接态与数据新鲜度可见
系统必须持续展示实时通道状态（已连接、正在连接、轮询降级、已断开重试）以及最近一次成功快照的本地可读时间。连接态变化必须写入一处状态区域，不得用多个互相抢播的实时区域只播报裸数字。

#### Scenario: 实时通道建立后显示已连接
- **WHEN** 检测页成功连上 `/ws/observe`
- **THEN** 连接态区域显示已连接或等价中文，并带正常态图标
- **AND** 总览区显示该次快照的生成时间

#### Scenario: 实时通道失败后降级轮询
- **WHEN** 实时通道超时或断开且页面改用轮询拉取 `/api/observe`
- **THEN** 连接态区域用中文写明轮询或重连，而不是空白
- **AND** 只要快照接口仍成功，对局与指标继续刷新

### Requirement: 空态加载与读取异常可恢复
系统必须区分首次加载、当前无对局、观测接口失败三类空画面。无对局时必须给出说明性空态，而不是空白主区。观测读取失败时必须在页面顶部给出中文错误，并保留手动或自动重试路径。不得提供任何会改写对局或投递状态的控件。

#### Scenario: 没有对局时看到说明而不是空白
- **WHEN** 快照成功且活跃对局数为零
- **THEN** 对局区显示「当前没有正在进行的对局」或等价说明
- **AND** 总览指标、全局日志与异常投递区仍然可见

#### Scenario: 快照接口失败时顶部告警
- **WHEN** `/api/observe` 返回失败或快照载荷自带错误列表
- **THEN** 页面顶部出现可被辅助技术识别的错误摘要
- **AND** 错误文案为中文，说明观测读取失败，而不是未捕获的脚本中断

### Requirement: 检测页自包含且只读
`/dashboard` 必须继续由服务端直接返回完整超文本，不依赖外链样式表、脚本或字体即可完成首屏与后续刷新。页面必须保持只读：不得新增会调用写接口或改动游戏状态的按钮。`/healthz` 与 `/readyz` 的机器可读语义必须保持不变。

#### Scenario: 断网外链仍能渲染检测页
- **WHEN** 浏览器无法访问任何第三方域名
- **THEN** 检测页的布局、字体回退与脚本刷新仍可工作
- **AND** 页面源码不请求外链字体或外链脚本

#### Scenario: 页面上没有改局控件
- **WHEN** 运维浏览检测页全部可点区域
- **THEN** 可点控件仅用于展开折叠、聚焦或重试读取
- **AND** 不存在开始游戏、踢人、重发消息等会改写对局的操作

### Requirement: 键盘与减弱动效能用完检测页
所有可操作控件必须能用键盘到达，焦点环必须可见，折叠区必须暴露展开或收起状态。标题层级必须从一级标题顺序向下，不得跳级。非必要动画必须尊重系统「减少动态效果」偏好。粘性顶栏不得完全挡住当前焦点控件。

#### Scenario: 只用键盘展开房间明细
- **WHEN** 运维使用键盘在对局卡片上移动焦点并激活折叠标题
- **THEN** 对应明细展开或收起
- **AND** 焦点环始终可见，且折叠控件的展开状态可被辅助技术读出

#### Scenario: 系统要求减少动态效果时不再位移入场
- **WHEN** 用户代理声明减少动态效果
- **THEN** 检测页不播放位移或闪烁类入场动画
- **AND** 状态切换仍可通过颜色、图标与文字立即到达终态

### Requirement: 窄屏下检测页可纵向阅读
在窄视口下，系统必须把健康摘要、指标卡片与对局卡片改为单列纵向排列，页面本身不得出现整页横向滚动。宽表格必须在卡片内部横向滚动，而不是撑破视口。

#### Scenario: 手机宽度下指标改为单列
- **WHEN** 视口宽度约为三百七十五个设备像素
- **THEN** 指标卡片与对局卡片按单列堆叠
- **AND** 页面根层不出现横向滚动条
