## Why

`/dashboard` 是仓库里唯一的运维检测页，用来判断对局卡在「等人」「定时器没跑」还是「消息没发出去」。当前页面是深色调试控制台：顶栏指标挤成一行、诊断结论和表格样式接近原始转储，运维扫一眼很难建立企业级健康感。现在要在不改游戏与只读接口的前提下，把它做成可扫描、可访问、状态语义清晰的企业级检测台。

## What Changes

- 重排 `/dashboard` 信息架构：左侧品牌与分区导航，右侧顶栏连接态，工作区依次为服务健康条、指标卡片、房间诊断卡、全局日志与异常投递
- 用语义色、文字标签与内联矢量图标共同表达正常 / 提示 / 警告 / 错误，禁止只靠颜色区分
- 补齐空态、加载态、断连/轮询态、观测读取异常的可见反馈与恢复说明
- 保持页面自包含、不依赖外链字体或脚本；快照、房间详情、实时通道行为保持只读
- `/healthz` 与 `/readyz` 仍为机器可读接口，不改状态码语义；检测页顶栏复用已有快照字段展示网关等健康信息
- 更新观测页相关说明（如 `README.md`、`docs/游玩教程.md`）以匹配新版布局用语

## Capabilities

### New Capabilities

- `observe-dashboard`：后台实时检测页的信息架构、状态语义、空态与无障碍呈现约定

### Modified Capabilities

- （无；仓库尚无已归档的主 specs）

## Impact

- `adapters/web/dashboard.py`：主要改 `DASHBOARD_HTML` 的结构、样式与前端渲染；后端快照拼装保持只读，除非为展示分组做纯展示字段
- `main.py`：路由仍为 `/dashboard`、`/api/observe`、`/ws/observe`，不新增写接口
- 测试：为内嵌页补结构/无障碍断言，或为快照字段与页面关键区域做静态检查
- 文档：`README.md`、`docs/游玩教程.md` 中观测页描述与新布局对齐
- 运行时：运维打开同一地址即可看到新版检测台；不要求改部署端口或鉴权模型
